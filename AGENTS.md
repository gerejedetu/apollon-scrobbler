# Scrobbler: guide for coding agents

A ListenBrainz-compatible scrobbler that runs on Cloudflare Workers (Hono + Turso/libSQL or D1 + KV), with accounts and
user tokens from Better Auth. Monorepo managed by Vite+ (`vp`) and pnpm workspaces.

## Layout

```
apps/
  web/            Front (TanStack Start + Panda CSS + Zag.js) on its own Worker. Relays /api/auth, /v1 and /1
                  to the API through a service binding (same origin = first-party Better Auth cookies).
  mcp/            Remote MCP server (Streamable HTTP, stateless) on its own Worker: MCP tools over /v1, through a
                  service binding, with the caller's own token. Deployed at <web origin>/mcp by a Worker route.
  api/            Hono Worker. src/protocols/native → /v1 (own JSON API, OpenAPI at /v1/openapi.json),
                  src/protocols/listenbrainz → /1 (ListenBrainz-compatible), Better Auth → /api/auth
packages/
  types/          Wire (ListenBrainz) and domain types. No runtime code.
  core/           Business rules behind ports. No I/O, no Cloudflare, no Better Auth.
  db-d1/          The SQLite repositories (written against a D1-shaped driver) + all SQL migrations
  db-libsql/      Turso / libSQL driver for those same repositories (production database)
  cache-kv/       Workers KV implementation of core's Cache
  auth/           Better Auth setup (username + API key plugins) + core's TokenVerifier
  client/         Typed client of the native API (/v1) over any fetch-like transport (web front, MCP server)
  testing/        Node-only doubles: D1 on node:sqlite, KV in memory
```

## Dependency rules (keep them)

- `types` depends on nothing. `core` depends only on `types`. `client` depends on nothing (it mirrors the wire format).
- Adapters (`db-*`, `cache-*`, `auth`) depend on `core` and `types`, never on each other or on apps.
- Only `apps/api/src/http/container.ts` picks concrete adapters. Routes talk to `c.var.services` only.
- A protocol (`apps/api/src/protocols/<name>`) only maps its wire format to core services; rules live in core,
  so every protocol behaves the same. A new protocol (e.g. Last.fm) is a new folder mounted in `app.ts`.
- The native API is documented by hand: shapes in `protocols/native/openapi.ts`, prose (overview, tags, operation and parameter descriptions, examples) in `openapi-docs.ts`. Tests check every documented path is routed, every response field is documented, and every operation/parameter has a description. Served at `/v1/openapi.json`, browsable at `/v1/docs`.
- `testing` and every `*/testing` subpath are for tests: never import them from runtime code.
- Internal packages are consumed as TypeScript source (`exports` points to `src/index.ts`); no build step.
- Imports use explicit `.ts` extensions. One module per folder with an `index.ts` or a named file; no catch-all utils.

## Web front (apps/web)

- `src/edge` relays API paths (service binding `API`; `API_ORIGIN` in `.dev.vars` for local dev). `src/server.ts` is the Worker entry.
- `src/api` is the only way to reach the API: `transport.ts` (browser fetch, or the binding with the request's cookie during SSR) plugged into `@scrobbler/client` (`packages/client`: `http.ts`, `endpoints.ts` with one function per /v1 operation, `types.ts` with the shapes from the OpenAPI). New /v1 operations go in the client package, not in the app.
- `src/auth`: Better Auth client, viewer (GET /v1/me) and route guards. `src/lib`: French formatting, ranges, time zone.
- `src/ui`: Apollon design system (brand name, mark and page titles in `ui/brand`, theme tokens in `ui/theme`, primitives, covers, charts, Zag-driven switch/tabs/clipboard). No data fetching there.
- Covers: every image goes through `/covers` (`src/edge/covers.ts`): resolved once (Cover Art Archive by MBID, else Deezer by name with
  strict name checks, MusicBrainz aliases across scripts, else the listen's YouTube thumbnail), stored in R2 (`ARTWORK`, bucket
  `apollon-artwork`) and served with immutable headers; misses are stored as markers. Bump `RESOLVER` to retry stored misses,
  the storage prefix to re-resolve found images, and `LOOKUP_VERSION` (ui/cover/artwork.ts) when browsers must drop cached answers.
  Warm-up: `vpx scripts/warm-covers.ts <origin> <user>`. With no artwork the cover is a neutral tile with a note (theme tokens).
- `src/features/<screen>`: one folder per screen, composing `ui` with data. `src/routes` only wires loaders to features.
- Dates are formatted in UTC after shifting by the viewer's offset (`lib/timezone.ts`, cookie `utc_offset` for SSR) so server and browser render the same text.
- Panda 2 output (`styled-system/`) is generated by `prepare` and git-ignored. Deploy: `cd apps/web && vp run deploy`. Icons in `public/` are rendered from `brand/*.svg` by `sh brand/render.sh`.

## MCP server (apps/mcp)

- Auth: Better Auth's `mcp` plugin (packages/auth) makes the API an OAuth 2.1 server (dynamic client registration, PKCE,
  JWT access tokens audience-bound to `<origin>/mcp`); the web front hosts its login (`/connexion`) and consent
  (`/autoriser`) pages and relays `/.well-known/oauth-*` to the API. The API accepts those JWTs like API keys
  (`tokenVerifier`), so the MCP Worker just forwards the header, keeping the public origin for the audience check.
- `src/http/handler.ts` serves `/mcp`: checks `Authorization: Bearer|Token <token>`, resolves the caller once (GET /v1/me,
  cached per isolate for 60 s like the API's own token cache), then builds a fresh `McpServer` + stateless transport per request.
- `src/tools/<area>.ts` registers tools for one area (listens, stats, library, search, favourites) on `ToolContext`
  (`api` = `@scrobbler/client` endpoints, `me`). Tools only call the API, never the database: the API keeps its rules,
  private profiles and rate limits. API errors become tool errors with a hint (`tools/result.ts`).
- Keep each tool to one API request (the cost test checks it); search matches within the cached all-time tops (`src/search`).
- Descriptions are written for the model: say what comes back, the units, and which tool gives the names a tool needs.
- Tests (`tests/`) run an MCP SDK client against the handler in front of the real API on the test database
  (`@scrobbler/api/testing`). Deploy: `cd apps/mcp && vp run deploy` (routes from git-ignored `.env.cloudflare`).

## Adding a storage backend

Implement `Repositories` from `@scrobbler/core` (see `packages/db-d1/src/repositories/*` for the reference
behaviour) in a new `packages/db-<name>`, test it with the same cases as `packages/db-d1/tests`, then switch
the container. Better Auth needs its own adapter for that database too.

## Database (Turso)

- Production runs on **Turso** (libSQL). `packages/db-libsql` adapts a libSQL client to the D1-shaped driver the
  repositories in `packages/db-d1` are written against, so Turso and D1 run the _same_ SQL, migrations and tests,
  and Better Auth uses the same driver. The API picks Turso when `TURSO_DATABASE_URL` is set (Worker secrets
  `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`), else a `DB` D1 binding if one is configured (none is: production deleted its D1 database).
- Turso schema: `vp run @scrobbler/api#db:migrate` (applies `packages/db-d1/migrations`, tracked in
  `_migrations`); `db:status` lists migrations and row counts. Credentials come from `apps/api/.env.turso`
  (git-ignored, see `.env.turso.example`).
- `vp run @scrobbler/api#test` runs the API suite twice: on the D1 double and on libSQL (`TEST_DB=libsql`).
- Turso bills rows read (every row a query _scans_, aggregates included, and an UPDATE reads what it changes)
  and rows written: keep every query index-bounded (the query-plan test enforces it), never `count(*)` a growing
  table at request time (use maintained counters such as `users.listen_count`), batch writes.

- Migrations live in `packages/db-d1/migrations`, applied to Turso by `apps/api/scripts/turso.ts` (`vp run @scrobbler/api#db:migrate`), tracked by file name and applied in name order. Never edit or rename one that is applied: add the next number. (If a rename is ever unavoidable, update its row in `_migrations` in the same step, or it runs again.)
- `0001_auth.sql` is generated: `vp run @scrobbler/auth#migration` prints it. Regenerate when Better Auth or its plugins change, and add a new numbered migration for the difference rather than editing an applied one.
- Query budget matters (Turso counts every row a query scans; D1 also limits statements per invocation and bound parameters):
  - batch inserts go through one `json_each` statement per ~900 KB of listens;
  - `users.listen_count` and `users.data_version` are maintained in the same batch via `changes()`, never by counting;
  - every listen read is bounded by an index on `(user_id, listened_at, …)` or `(user_id, artist_name, …)` (tests/query-plans.test.ts);
  - stats are cached per isolate for every user, and in KV too above `CACHE_MIN_LISTENS` (500 on Turso), keyed by
    `users.data_version`: any change to a user's listens (insert, delete, merge) refreshes them. Anything that changes listens
    outside the repositories (scripts) must bump `data_version`.
- Names are normalized at ingest (core `artists/names.ts`, `albums/names.ts`): a bilingual credit ("헤이즈 Heize") joins the
  artist the library already has and its other forms are learned in `artist_aliases`; content advisories ("[Clean]") are dropped
  and an edition ("(Deluxe)") joins the plain album when the library has it. Only names with a marker cost a lookup.
  Existing duplicates: `vpx scripts/turso.ts merge-artist|merge-album` in apps/api.
- Artist-level stats count a joint credit ("A & B", "A feat. B") for each artist: core's `splitArtistCredit` decides
  the split, `artist_credits` (0005) stores it for joint credits only, written in the insert batch; queries go through
  `packages/db-d1/src/artists.ts`. Tracks and albums keep the credit as written. After changing the split rules,
  rerun `vp run db:backfill-credits` in apps/api and bump the stats cache key version.
- Tests assert round trips through `SqliteD1.roundTrips`; keep hot paths at one round trip.

## Auth

- Accounts, sessions and API keys are Better Auth's (`user`, `session`, `account`, `verification`, `apikey`), plus the OAuth
  provider's tables for MCP clients (`oauth*`, `jwks`, migration 0008).
- A ListenBrainz user token is a Better Auth API key, sent as `Authorization: Token <key>`.
- The scrobbler profile (`users` row) is created by the `user.create.after` hook; its `name` is the username.
- Private profiles (`users.is_private`): every read of a user's data goes through `readableUser()` (apps/api/src/http/require-user.ts), which 404s for anyone but the owner. New read routes must use it.
- Token checks are cached per isolate for 60 s (`AUTH_CACHE_TTL`), so a revoked key keeps working up to that long.

```
vp install            # after pulling

```

## Conventions

- Errors leave the API as `{ "code": <status>, "error": "<message>" }` (`ApiError` in core).
- Timestamps are Unix seconds (UTC) everywhere.
- Every module gets tests; behaviour that mirrors ListenBrainz cites its rule in a comment.
- Never commit secrets or account-specific IDs: `.dev.vars`, `.env*` are ignored; production secrets go through `wrangler secret put`. `wrangler.jsonc` keeps a placeholder KV ID; the real one lives in `apps/api/.env.cloudflare` and `vp run deploy` injects it. Turso credentials live in `apps/api/.env.turso` and in Worker secrets.
